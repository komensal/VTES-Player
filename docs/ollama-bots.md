# Local Ollama bots and comparison

Ollama is an optional, local decision service, not a training algorithm. Install Ollama on the computer running the Vite dev server, start it, and install the model named in **Settings → Bots** (default `qwen3:8b`). Use **Test Ollama connection** there and save settings. Open the game on `localhost` or `127.0.0.1`; the local-only bridge is intentionally unavailable on the static site, over a LAN, or from the Arena cloud preview. Restart the Vite server after updating the project. Ollama and its selected model are separate installations and are not bundled with the game.

In **Your table**, choose a style per bot seat. The default uses Settings/deck style; any seat can instead choose Balanced, another heuristic, the saved trained or neural policy, or Ollama. Several seats may use Ollama: they share the local service/model, but each request has only the acting seat's masked `PlayerView`. A seat's style is retained by a save; the model tag is a local setting and is not embedded in the save. Hosts run bots for online tables, so Ollama must run on the host's computer. The trained/neural selections use their existing fallback if the corresponding saved profile is missing.

The Ollama agent includes relevant short rule summaries and printed text for cards visible to the acting player. These are automatically selected context, **not** a full rulebook upload or interactive rule-search tools. The prompt contains the legal option IDs; the model picks an ID and never mutates the game. The engine remains the authority. A failed block that cannot currently succeed is excluded when an alternative exists (same safety rule used by the heuristic bot). Single or forced safe choices do not call the LLM. All other choices currently do; several Ollama seats may make a game slow. If the service is unavailable, times out, returns invalid JSON or an illegal ID, the agent uses the Balanced heuristic and reports a notice in the game log. Asynchronous requests are cancelled on a rewind or agent change and stale answers are discarded.

The local Vite bridge accepts only same-origin requests from a loopback client on a loopback host and talks only to `127.0.0.1:11434`; it is not a generic proxy. Ollama prompts include the acting bot's private hand, so use only a local Ollama installation you trust. No requests are sent to a cloud LLM by the application.

## Comparing bots

**AI Training Lab → Bot comparison** runs two selected policies in matched games: for each seed and each of five candidate seats, A and B separately receive the same initial setup, seat, deck, and opponent agents. Opponents and deck assignments are identical *within each pair*; play can diverge afterwards. One deal is 10 games. The included three playtest deck snapshots are repeated on the five-seat table, so results are not a universal measure of every VTES deck. Neural evaluation is greedy, without PPO exploration. The panel reports VP, wins, average time for non-forced decisions, and LLM request count. Cancellation retains only completed pairs. A game that used Ollama fallback is not scored as an LLM game: the comparison stops with an error instead. Tiny samples are noisy and a fixed seed is not a substitute for independent evaluation. LLM outputs may not be reproducible even with identical initial seeds.
